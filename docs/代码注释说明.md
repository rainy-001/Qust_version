# 代码注释说明（`// [解析]` 标记）

本文说明本项目注释的**标记约定**、**密度规则**、**覆盖范围**、
**如何只看自己的代码 / 一键删除**，以及**验证方式**与**发现的代码疑点**。

---

## 1. 为什么要有这个约定

本项目的 `sp_middleware/` 来自**同济 SP 战队开源的 RoboMaster 电控中间件**，
`Core/` 大部分是 **STM32CubeMX 自动生成**的 HAL 代码。

这两部分都**自带大量原注释**（doxygen 块、CubeMX 的 `/* USER CODE BEGIN */` 标记、
原作者的中文说明）。直接往里加注释会导致"分不清哪句是原作者写的、哪句是后来补的"，
改代码时既容易误删原注释，也容易破坏生成代码的保护标记。

所以约定：**所有后来新增的解释性注释，一律以 `// [解析] ` 开头。**
（半角方括号，方括号后跟一个空格）

---

## 2. 密度规则（重要）

注释的目标是**帮人快速建立"这段在干什么"的印象**，不是逐行翻译代码。
按行解释反而会把代码淹没，所以本项目的注释遵守下面的密度：

| 位置 | 写多少 | 写什么 |
|---|---|---|
| 文件开头 | **3~6 行** | 这个文件是什么 / 谁在用、在整条链路里的位置 / 最需要先知道的一个点 |
| 类、结构体、函数之前 | **1~3 行** | 它做什么、被谁调用、关键原理。**简单 getter、构造函数、一眼能懂的短函数不写** |
| 函数体内 | **每个函数最多 1~2 处**，每处 1~2 行 | 只给真正非显而易见的部分：协议位域、魔数与量程换算、CRC、中断安全、DMA/缓冲区复用、定点浮点换算、反直觉的符号与单位 |
| 单条语句 | **不写** | 赋值、函数调用、`return`、`for`/`if` 头不单独解释 |
| 行尾 | **不写** | 不使用 `x = 1;  // [解析] ...` 这种行尾注释 |

**量化目标：`[解析]` 行数约为代码行数的 1/6 ~ 1/8，硬上限不超过 1/5。**

当前实际密度：**1 行注释 / 6.9 行代码**。

写错地方的典型反面例子（不要这样写）：

```cpp
// [解析] 下面是循环                          <- 废话
for (int i = 0; i < 8; i++) {
  // [解析] 取第 i 位                       <- 逐行翻译，删掉
  // [解析]   1) 移位  2) 与 1  3) 三目      <- 把一个表达式拆成 4 行，删掉
  buff_[7 - i] = (((g >> i) & 0x01) ? CODE1 : CODE0) >> 1;
}
```

正确的写法是只在**函数级**交代清楚，让读者自己去读那三行代码：

```cpp
// [解析] 逐位把 RGB 编成 SPI 码流：每一位扩成 4 个 SPI 位，
// [解析] 0 用短高电平(0xC0)、1 用长高电平(0xF0)，倒序填充以满足 WS2812 高位先出。
void WS2812::set(uint8_t r, uint8_t g, uint8_t b)
```

## 4. 怎么只看"自己的代码"

`[解析]` 这个标记在全项目里是唯一的，所以过滤很干净。

**隐藏全部新增注释，只看原有逻辑**：

```bash
grep -v '\[解析\]' applications/can_task.cpp                   # Git Bash / Linux / macOS

Select-String -NotMatch '\[解析\]' applications\can_task.cpp    # PowerShell
```

**只显示新增注释（当学习笔记读）**：

```bash
grep -n '\[解析\]' sp_middleware/tools/gimbal/gimbal.cpp

Select-String '\[解析\]' sp_middleware\tools\gimbal\gimbal.cpp
```

**VS Code**：直接全局搜索 `[解析]`，即可列出所有新增注释的位置。

**看每个文件加了多少行**：

```bash
git diff --numstat        # 第一列=新增行数，第二列=删除行数
```

## 5. 怎么撤销 / 删除这些注释

**最安全、最推荐的做法**——直接丢弃改动，回到加注释之前：

```bash
git checkout -- applications sp_middleware
```

**只想删掉新增注释行、保留其他改动**（先预览再执行）：

```bash
grep -rn '\[解析\]' applications sp_middleware | wc -l          # 预览
grep -rl '\[解析\]' applications sp_middleware | xargs sed -i '/\[解析\]/d'
```

> 现在的注释**全部是整行注释，没有行尾注释**，所以 `sed -i '/\[解析\]/d'` 不会误删代码。
> 删完建议 `git diff` 再看一眼。

## 7. 验证方式（怎么确认"只动了注释"）

本次改动通过了**四层独立验证**，脚本都在 `build/`（该目录已 `.gitignore`）：

| # | 验证 | 方法 | 结果 |
|---|---|---|---|
| 1 | **代码一致性** | `verify_strict.py`：保留缩进、逐行比对"代码行"序列（注释和空行被忽略） | 100/100 文件**逐字符一致** |
| 2 | **原注释保全** | `verify_originals.py`：取 HEAD 里每行"非 `[解析]` 的注释"，要求在当前文件中仍存在 | **1239 行项目自带注释全部保留，0 丢失** |
| 3 | **二进制比对** | 重新编译后对比 `.text` / `.rodata` / 去调试 ELF / 完整 bin 的 SHA256 | 四项**全部逐字节相同**；FLASH 仍为 52388 B |
| 4 | **编译回归** | `cmake --build build/Debug` 全量构建 | 通过，无新增错误或警告 |

## 8. 发现的代码疑点（**均只标注、未修改代码**）

代码里仍保留了最关键的一两句提醒（`// [解析] 注意：`），完整说明在本节。
按"值得优先确认"排序：

### 会影响正确性的

1. **`rm_motor.cpp` 减速比被算了两遍、相互抵消**：`get_raw_to_torque()` 里已除过 `ratio_`，
   `read()` 里又乘了一次，于是 M2006/M3508 读回的 `torque` 与手册 N·m **对不上**。
   `cmd()` 方向自洽，闭环能用，但绝对值不可对账。`*10/*20/*3` 三个系数来历也找不到依据。
2. **`bmi088.cpp` 陀螺仪标度因数公式疑似笔误**：
   `2000.0f / (BMI088_GYRO_RANGE_SET + 1) / 32767` 应为 `2000.0f / (1 << ...) / 32767`。
   本项目固定 2000dps（n=0），**当前结果正确**，但改小量程后角速度会整体偏大。
3. **`fuzzy_pid.cpp` 的 D 项少了 `/ dt_`**：`pid.cpp` 是 `kd_ * dbuf[0] / dt_`，
   模糊版是 `fuzzy_kd * dbuf[0]`，两者 `kd` 量纲差 `dt_`（1kHz 下 1000 倍），**不能照抄参数**。
4. **`ddt_motor.cpp` 角度除数是 32767 而非 65535**：`angle_int` 是 uint16，
   角度会一路涨到约 4π 再被折回，很可能应为 65535。
5. **`diff_drive.cpp` 的 `update()` 旋转速度符号疑似写反**：
   `(sign_l_*speed_r - sign_r_*speed_l)` 应为 `(sign_l_*speed_l - sign_r_*speed_r)`。
   该模块**全工程无人调用**，所以一直没暴露。
6. **`joint_controller.cpp` 的 `init_angle_` 未乘 `sign_`**：`reverse = true` 时
   零点位置与直连情况不对称，疑似笔误。
7. **`vision.cpp` 溢出处理不完整**：只把 `rx_len_` 清零；若单次 `len` 大于
   `rx_buffer_` 的 512 字节，`std::copy` 仍会越界写。
8. **`led.cpp` 亮度顶到 1.0 会溢出**：算的是 `(ARR+1) * 亮度`，ARR 固定 65535，
   填 1.0 得 65536 被截断（可能表现为灯灭而非最亮）。通道对应是 **CH1=蓝/CH2=绿/CH3=红**。

### 编译 / 构建层面的

9. **`printf` 是断的**：`syscalls.c` 的 `__io_putchar` / `__io_getchar` 只有 `weak` 声明、
   全工程没有定义。一旦调用 `printf` 会跳到 0 地址 **HardFault**。要用串口打印得自己实现。
10. **`syscalls.c` / `sysmem.c` 没有 `USER CODE` 保护区**，CubeMX 重新生成会整份覆盖。
11. **引脚信息有两处来源**：`imu_task.cpp` 硬编码 `GPIOA, GPIO_PIN_4` / `GPIOB, GPIO_PIN_0`，
    没用 `main.h` 的宏。改引脚必须同时改两处。
12. **`system_stm32f4xx.c` 的 `HSE_VALUE` 兜底值仍是 25 MHz**（本工程 12 MHz）。
    目前被 `hal_conf.h` 覆盖所以不生效，一旦该定义变动，波特率与 CAN 位时序会偏 25/12 倍。
13. **`INCLUDE_vTaskDelayUntil = 0`**：`osDelayUntil()` 编译能过、运行时会静默返回错误。

### 硬件配置 / 文档不一致

14. **SPI1 的 MISO 文档与代码矛盾**：`docs/C板引脚配置说明.md` 写 `PB3/PA6/PA7`，
    而 `spi.c` 与 `.ioc` 实际是 **PB4**。按文档接线会读不到 IMU。
15. **PB3 / PB4 复位后默认是 JTAG 引脚**，工程里未见 `__HAL_AFIO_REMAP_SWJ_NOJTAG()`。
    IMU 读不到数据时优先怀疑此处。
16. **ADC3 采样时间是 `ADC_SAMPLETIME_3CYCLES`**（文档写 56 cycles）。
    电池分压网络阻抗较高，3 个周期可能充不满采样电容，导致读数偏低/跳动。
17. **SPI1 = 10.5 Mbit/s 略超 BMI088 的 10 MHz 上限**（APB2 84MHz / 8）。
18. **`can.cpp` 打开了 RX_FIFO1 的中断通知，但 `can.c` 只使能了 `CAN1_RX0_IRQn`**，
    也没有 FIFO1 回调——这段是"死配置"。
19. **TIM1 被 HAL 时基独占**（PSC=167 / ARR=999 锁死），与文档第 7 节把
    `TIM1_CH1~CH4` 列为舵机 PWM 可扩展项**不能并存**。
20. **`can.c` 里 `AutoBusOff` / `AutoRetransmission` 都是 `DISABLE`**：
    Bus-Off 后不自动恢复、出错帧直接丢弃。

### 健壮性 / 边界

21. **`super_cap::is_alive()` 缺首帧保护**：`last_read_ms_` 未初始化，
    且没有先用 `is_open()` 短路。
22. **`vt02` 只处理 `0x0302`**，`mouse`/`keys` 永远是默认值；`memcpy` 前未校验 `data_len`。
23. **`vt03::update()` 在 CRC 校验之前就置 `has_read_/last_read_ms_`**，
    收到任意字节（哪怕 CRC 全错）`is_alive()` 就为真。
24. **`referee/ui` 的 `Element` / `UI_Manager` 构造时不清零内部结构体**，
    必须定义成全局/静态对象，否则会发出脏数据。
25. **`crc.cpp` 的 `check_crc8/check_crc16` 缺长度下限保护**：传 `len=0` 会 `data[-1]` 越界。
26. **`math_tools.cpp` 的 `float_to_uint` 不限幅**；`dm_motor.cpp` 的
    `data[6] = torque_uint >> 8` 依赖"结果 ≤ 0xF"这一前提。
27. **`cybergear_motor`：`CYBERGEAR_MAX_SPEED = 30.0f` 但注释写 300rpm（31.42 rad/s）**；
    且这些量程宏在类里并未使用（真正生效的是构造参数）。
28. **`lk_motor.cpp` 的 `get_ecd_range()` 两个分支返回值相同**，等于没有分支。
29. **`mahony.hpp` 的 `dq[4]`、`acc_euler[3]` 全工程无赋值处**，读到的却是未初始化内存。
30. **各驱动普遍忽略 HAL 返回值**，SPI 出错时表现为"读到旧数据"而非报错，排查困难。

> 另外：根目录的 **`build_errors.txt` 是过期文件**，
> 记录的是 `vision` 模块尚未从 `CMakeLists.txt` 注释掉之前的失败信息。
> 当前工程 `cmake --build build/Debug` **可以完整编译通过**。
